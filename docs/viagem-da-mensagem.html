Glossário

      
    

    
Infraestrutura

      
Codespaces
Um computador Linux na nuvem do GitHub, criado a partir de um repositório e usado pelo navegador. É onde o kit inteiro roda.

      
Contêiner (container)
Uma “caixa” isolada que roda um programa com tudo de que ele precisa: sistema, bibliotecas e configurações. Vários contêineres rodam na mesma máquina sem um atrapalhar o outro.

      
Docker
A ferramenta que cria e roda os contêineres a partir de imagens, que são os modelos prontos de cada programa.

      
docker compose
Comando do Docker que liga um grupo de contêineres de uma vez, descrito num arquivo docker-compose.yaml. O kit tem um grupo para o Dify, um para o Chatwoot e um para os seus serviços.

      
Porta
Número que identifica um serviço dentro de uma máquina: 8080 é o painel, 3000 o Chatwoot, 8081 o Dify. O Codespaces transforma cada porta num endereço …-8080.app.github.dev.

      
Rede interna
Rede privada entre os contêineres (no kit, kit-rede). Por ela um contêiner chama o outro pelo nome, como http://chatwoot:3000, sem passar pela internet.

      
Volume
Pasta que fica fora do contêiner e sobrevive quando ele é recriado. É onde ficam os bancos de dados e a pasta config/.

    

    
Web e comunicação

      
API
Uma “porta de entrada” para programas: endereços que outro programa chama para pedir ou enviar dados, em vez de uma pessoa clicar numa tela.

      
Blocking e streaming
Duas formas de receber uma resposta: blocking espera o texto inteiro ficar pronto; streaming vai mostrando aos pedaços. O conector usa blocking.

      
Cookie
Pequeno dado que o site guarda no navegador para reconhecer você na próxima visita. O cw_conversation diz ao Chatwoot qual é a sua conversa.

      
Códigos de status
Número que resume a resposta HTTP: 200/201 deu certo; 400 pedido com problema; 401/403 sem permissão; 404 não encontrado; 422 dado inválido; 429 pedidos demais; 500/503 erro ou serviço indisponível.

      
HTTP
O protocolo da web. Cada pedido tem um método (GET para buscar, POST para enviar) e cada resposta tem um código de status.

      
iframe
Uma página dentro de outra página. O balão do chat é um iframe do Chatwoot dentro do painel.

      
JSON
Formato de texto para trocar dados entre programas, com chaves e valores: {"category_id": "servicos"}.

      
postMessage
Jeito seguro de uma página e um iframe de endereços diferentes trocarem mensagens.

      
Proxy reverso
Um intermediário que recebe os pedidos num endereço e os repassa a outro serviço, devolvendo a resposta como se fosse dele. O painel faz isso com o Chatwoot.

      
SSRF
Ataque em que alguém faz um servidor chamar endereços internos que não deveria. Por isso o Chatwoot bloqueia webhooks para a rede interna, a menos que seja liberado, e o Dify passa as chamadas pelo ssrf_proxy.

      
Timeout
Tempo máximo de espera. Passou disso, o pedido é cancelado. O conector espera até 60 segundos pelo Dify.

      
Token / chave de API
Uma senha para programas. Vai no cabeçalho do pedido (Authorization: Bearer app-…) e diz quem está chamando e o que pode fazer.

      
Webhook
Um aviso automático: quando algo acontece num sistema, ele chama o endereço de outro sistema. O Chatwoot chama o conector a cada mensagem nova.

      
Websocket
Conexão que fica aberta entre o navegador e o servidor, para o servidor mandar novidades na hora, sem a página precisar perguntar. O ActionCable é o websocket do Rails, usado pelo Chatwoot.

    

    
Programas e linguagens

      
Expressão regular (regex)
Um padrão para procurar texto. O nó “Validar número” usa uma para achar números de processo no formato CNJ.

      
FastAPI
Biblioteca Python para criar APIs e páginas web com pouco código. O painel, o conector e as APIs simuladas são feitos com ela.

      
httpx
Biblioteca Python para fazer pedidos HTTP. É com ela que o conector chama o Dify e o Chatwoot.

      
nginx
Servidor web que fica na frente do Dify e distribui os pedidos entre a API e as telas.

      
Plugin
Peça que se instala no Dify para ele falar com um provedor de IA (Groq, NVIDIA NIM, Gemini).

      
PostgreSQL
Banco de dados onde Chatwoot e Dify guardam conversas, contas, fluxos e a base de conhecimento.

      
Python
Linguagem de programação do painel, do conector, das APIs simuladas e dos nós de código do Dify.

      
Redis
Banco de dados em memória, muito rápido, usado como cache e para as filas de tarefas.

      
Ruby on Rails
Linguagem Ruby com o framework Rails, usados para construir o Chatwoot.

      
Sandbox
Ambiente isolado onde o Dify roda os nós de código, para um código com problema não afetar o resto.

      
Sidekiq
Fila de tarefas do Chatwoot: executa em segundo plano o que não precisa ser na hora, como enviar webhooks.

      
uvicorn
O servidor que roda uma aplicação FastAPI e atende os pedidos HTTP que chegam na porta.

    

    
Inteligência artificial

      
Alucinação
Quando o modelo inventa algo que parece verdade. Por isso o bot usa respostas fixas, APIs e a instrução de responder só com o contexto.

      
Base de conhecimento
Os documentos que o bot pode consultar. No kit, 5 artigos sobre os serviços do STJ.

      
Busca por palavra-chave
Encontrar trechos que têm as mesmas palavras da pergunta. É o que o kit usa (modo Econômico).

      
Classificador
Uso do modelo para escolher uma categoria entre várias, em vez de escrever texto livre.

      
Embedding
Transformar um texto numa lista de números que representa o significado. Permite a busca semântica, que acha “documento negativo” ao procurar “certidão negativa”. O kit não usa por padrão.

      
Few-shot
Colocar no prompt alguns exemplos prontos de pergunta e resposta, para o modelo imitar o formato. O classificador usa dois.

      
Janela de contexto
Quanto texto o modelo consegue considerar de uma vez. O gpt-oss-120b aceita cerca de 131 mil tokens.

      
LLM (modelo de linguagem)
Programa treinado com muito texto que lê uma instrução e escreve uma continuação. No kit, o gpt-oss-120b classifica a mensagem e redige a resposta.

      
Memória
As últimas mensagens da conversa enviadas junto com a pergunta, para o modelo entender o contexto.

      
Prompt
O texto enviado ao modelo: instruções, exemplos, contexto e a pergunta.

      
Provedor de IA
Empresa que roda os modelos na nuvem e cobra por uso: Groq, NVIDIA NIM, Google Gemini.

      
Raciocínio (reasoning)
Etapa em que alguns modelos “pensam” antes de responder; o reasoning_effort diz quanto. Quando o raciocínio toma o lugar da resposta, o Dify recebe texto vazio.

      
RAG
Retrieval-Augmented Generation: buscar trechos relevantes na base e entregá-los ao modelo junto com a pergunta, para ele responder com base neles. É o ramo “serviços” do Bot STJ.

      
Reranking
Uma segunda ordenação dos resultados da busca, feita por outro modelo, para pôr os mais relevantes no topo. Desligado no kit.

      
Temperatura
Controla a variação das respostas: perto de 0, o modelo escolhe sempre o mais provável; mais alto, fica mais criativo. O kit usa 0.2.

      
Token (de modelo)
Pedaço de texto que o modelo lê ou escreve, mais ou menos uma sílaba ou palavra curta. Cota e preço são contados em tokens.

      
top_k
Quantos trechos a busca devolve. No kit, 2.

      
Índice invertido
Tabela que liga cada palavra aos trechos onde ela aparece, como o índice remissivo de um livro.
